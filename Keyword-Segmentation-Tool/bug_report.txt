【C-01】visibleResults() 双重筛选导致结果不一致
------------------------------------------------------------------------------
  位置: index.html 第1346-1359行 visibleResults()函数
  问题: 
    函数同时使用 state.filterCat 和 state.filters.cat 进行分类筛选，
    但这两个值在某些情况下可能不同步，导致：
    a) 图例点击设置 filterCat 后，filters.cat 被清空，但搜索时仍检查 filters.cat
    b) 表头筛选设置 filters.cat 后，filterCat 未更新
    
  问题代码:
    ```javascript
    // 第1349行 - 检查 filterCat
    if(state.filterCat && r.cat!==state.filterCat) return false;
    // ...
    // 第1352行 - 又检查 filters.cat (冗余且可能冲突)
    if(f.cat && r.cat!==f.cat) return false;
    ```
  
  影响: 用户通过图例和表头筛选后，结果可能不符合预期，出现"筛不掉"或
       "多筛了"的现象
       
  修复建议: 统一使用一个筛选状态源，或在设置一方时同步另一方：
    ```javascript
    // 方案: 在函数入口统一
    const activeCatFilter = state.filterCat || state.filters.cat;
    if(activeCatFilter && r.cat !== activeCatFilter) return false;
    ```


【C-02】AI分类 JSON 解析缺乏容错，异常会导致整个批次失败
------------------------------------------------------------------------------
  位置: index.html 第1332-1335行 aiClassify()函数
  问题:
    AI返回的内容直接用 JSON.parse() 解析，如果AI返回格式不正确
    （如包含markdown代码块标记、多余逗号、注释等），会抛出异常，
    整个批次的分类都会失败
    
  问题代码:
    ```javascript
    const content=j.choices&&j.choices[0]&&j.choices[0].message?j.choices[0].message.content:'';
    const parsed=JSON.parse(content);  // ← 可能抛出 SyntaxError
    ```
  
  影响: 网络请求成功但因解析失败，用户看到"AI分类失败"，无法获得任何AI结果
       
  修复建议: 增加容错处理
    ```javascript
    let parsed;
    try {
      // 尝试清理常见格式问题
      let cleaned = content.trim();
      if(cleaned.startsWith('```json')) cleaned = cleaned.slice(7);
      if(cleaned.startsWith('```')) cleaned = cleaned.slice(3);
      if(cleaned.endsWith('```')) cleaned = cleaned.slice(0, -3);
      cleaned = cleaned.trim();
      parsed = JSON.parse(cleaned);
    } catch(e) {
      console.warn('AI返回JSON解析失败，尝试提取:', content.slice(0,200));
      // 尝试正则提取或使用离线结果兜底
      parsed = {data: []};
    }
    ```

【M-02】筛选下拉框定位在表格滚动后偏移
------------------------------------------------------------------------------
  位置: index.html 第1666-1668行
  问题:
    筛选下拉框使用 getBoundingClientRect() 定位，这是相对于视口的坐标。
    当用户滚动表格后点击表头筛选，下拉框会出现在错误的位置（相对
    于视口而非表头）
    
  问题代码:
    ```javascript
    const rect=this.getBoundingClientRect();
    div.style.left=rect.left+'px';
    div.style.top=rect.bottom+'px';
    ```
  
  影响: 下拉框出现在屏幕上远离表头的位置，用户体验差
       
  修复建议: 使用 fixed 定位但考虑表格容器的滚动偏移：
    ```javascript
    const tableWrap = $('tableWrap');
    const wrapRect = tableWrap.getBoundingClientRect();
    div.style.left=rect.left+'px';
    div.style.top=(rect.bottom - wrapRect.top + tableWrap.scrollTop)+'px';
    div.style.position='absolute';
    tableWrap.appendChild(div);  // 改为挂载到tableWrap下
    ```


【M-03】CSV解析器不支持引号内换行和多字符分隔符混合
------------------------------------------------------------------------------
  位置: index.html 第1013-1030行 parseCSV()函数
  问题:
    a) 不处理引号内的换行符，导致带换行的CSV字段被错误分割
    b) 当用户输入同时包含换行和逗号的关键词时，parseManualKeywords 
       的分割逻辑可能产生意外结果
       
  示例问题数据:
    "关键词1,关键词2
    关键词3,关键词4"
    → 会被解析成 4 个而不是 2 个关键词
  
  影响: 导入某些格式的CSV文件时数据错乱
       
  修复建议: 增强CSV解析器或改用成熟的库（如PapaParse）


【M-04】全选checkbox与个别checkbox状态不同步
------------------------------------------------------------------------------
  位置: index.html 第1496-1508行 toggleAllChecked()函数
  问题:
    当用户手动取消勾选某些行后，全选checkbox会自动取消选中（正确）。
    但此时如果用户再点击全选checkbox选中它，期望行为应该是"选中所有行"，
    实际行为也是正确的。
    
    然而，问题在于：renderTable() 每次都重新创建DOM，checkbox的状态依赖
    state.checkedUnchecked，但在可见结果过滤变化时，原来未勾选的索引
    可能不再属于可见集合，导致UI显示与实际状态不一致。
    
  影响: 在筛选条件下，勾选状态显示混乱
       
  修复建议: 使用基于关键词内容而非数组索引的追踪方式


【M-05】性能问题：大量关键词时 classify() 反复构建正则表达式
------------------------------------------------------------------------------
  位置: index.html 第1161-1170行 classify()函数
  问题:
    每次调用 classify() 都会重新调用 buildRegex() 构建10+个正则表达式对象。
    对于1000个关键词，意味着构建10000+个正则对象。
    
    虽然 V8 引擎有正则缓存，但动态创建的正则不会被缓存优化。
  
  影响: 导入大文件（>5000行）时，分类耗时显著增加，可能造成界面卡顿
       
  修复建议: 将正则表达式缓存到 state 对象，仅在词典变更时重建：
    ```javascript
    // 在 readDictFromUI() 或 ingest() 末尾
    state._regexCache = {
      reQ: buildRegex(BASE.question.concat(D.ext.question)),
      reR: buildRegex(BASE.reputation.concat(D.ext.reputation)),
      // ... 其他正则
    };
    // classify()中使用缓存
    const reQ = state._regexCache.reQ;
    ```


【M-06】exportXLSX() 导出行数限制未明确提示
------------------------------------------------------------------------------
  位置: index.html 第1511-1529行 exportXLSX()函数
  问题:
    虽然渲染限制了2000条，但导出时会导出全部数据。当数据量非常大
    （如10万条）时：
    a) XLSX生成可能耗尽浏览器内存
    b) 生成的文件可能过大
    c) 没有进度提示，用户以为卡死了
    
  影响: 大数据量导出时浏览器可能崩溃无响应
       
  修复建议: 添加数据量检查和分片导出：
    ```javascript
    if(exportRows.length > 50000) {
      const confirmed = confirm(`即将导出 ${exportRows.length} 条数据，文件可能较大，是否继续？`);
      if(!confirmed) return;
    }
    ```

【m-04】设置抽屉关闭时无条件重新触发分类
------------------------------------------------------------------------------

    ```javascript
    function closeDrawer(){ 
      $('drawer').classList.remove('open'); 
      $('drawerMask').style.display='none'; 
      readDictFromUI();  // ← 总是读取

【m-05】置信度阈值滑块无边界校验
------------------------------------------------------------------------------
  位置: index.html 第1709行
  问题:
    ```javascript
    $('confTh').oninput=e=>{ 
      const v=parseInt(e.target.value,10); 
      state.confTh=v;  // ← 没有范围校验
    ```
    HTML中设置了 min="0" max="100"，但JavaScript没有防御性校验。

  修复: 添加范围约束 `state.confTh = Math.max(0, Math.min(100, v));`
