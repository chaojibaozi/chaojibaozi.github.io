【N-02】AI response_format 兼容性风险
------------------------------------------------------------------------------
  严重程度: 🟡 次要
  位置: 第1338行
  问题:
    const body={..., response_format:{type:'json_object'}, ...};
  分析:
    - response_format 是 OpenAI 新版 API 参数
    - 部分 DeepSeek 兼容接口或其他兼容 API 可能不支持此参数
    - 不支持时可能报错或被忽略（如果忽略则无影响）
  影响: 使用非标准 API 端点时可能触发 AI 分类失败
  建议: 可选方案
    a) 在 catch 中提供更好的错误提示
    b) 将 response_format 设为可选（通过设置面板开关控制）
    c) 文档说明支持的 API 类型
  优先级: 低（仅影响使用非标准 API 的用户）


【N-03】buildRegexCache 防御性调用的可读性问题
------------------------------------------------------------------------------
  严重程度: 🔵 建议
  位置: 第1174行
  问题:
    const C=state._reCache||(buildRegexCache(),state._reCache);
  分析:
    - 使用逗号表达式 `(expr1, expr2)` 返回 expr2 的值
    - 语法正确但可读性差，维护者可能不理解意图
    - 如果 _reCache 被意外设置为空对象 `{}`（非 null/undefined），
      则条件为 truthy，不会触发重建，可能导致使用过期缓存
  影响: 代码可维护性；极端情况下可能用过期缓存
  建议: 改为更清晰的写法
    if(!state._reCache) buildRegexCache();
    const C = state._reCache;
  优先级: 低（代码质量优化）
